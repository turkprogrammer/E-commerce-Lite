# Анализ текущего состояния проекта e-commerce

## 1. Общая архитектура

Проект следует принципам **гексагональной архитектуры** (Ports & Adapters), где бизнес-логика изолирована от внешних зависимостей. Архитектура разделена на следующие слои:

### Структура проекта:
```
src/
├── Domain/                    # Domain слой (Enterprise Logic)
│   ├── Entity/               # 8 чистых сущностей
│   └── Port/                 # Интерфейсы (порты)
├── Application/              # Application слой (Use Cases)
├── Infrastructure/           # Infrastructure слой (Adapters)
├── Controller/               # HTTP/CLI адаптеры
├── DataFixtures/             # Фикстуры для тестирования
└── Service/                  # Сервисы (в основном для админ-панели)
```

## 2. Доменная модель

### Сущности:
1. **Product** - Товар (название, цена, описание, категория, остаток)
2. **Category** - Категория товаров
3. **Cart** - Корзина покупателя (сессионная)
4. **CartItem** - Элемент корзины
5. **Order** - Заказ (данные покупателя, адрес доставки, статус)
6. **OrderItem** - Элемент заказа
7. **Payment** - Платеж
8. **User** - Пользователь (для админ-панели)

### Преимущества:
- Чистые сущности без зависимостей от фреймворка
- Все связи между сущностями реализованы через ORM Doctrine
- Используются PHP 8 атрибуты для маппинга

## 3. Слой приложения (Use Cases)

Реализованы следующие сценарии использования:

### Корзина:
- `AddItemToCart` - Добавить товар в корзину
- `GetCart` - Получить корзину
- `RemoveItemFromCart` - Удалить товар из корзины
- `CheckoutCart` - Оформить заказ из корзины

### Заказы:
- `CreateOrder` - Создать заказ
- `GetOrderByNumber` - Получить заказ по номеру
- `GetOrdersByEmail` - Получить заказы по email

### Платежи:
- `ProcessPaymentWebhook` - Обработка вебхука платежа

### Особенности:
- Все Use Cases покрыты unit-тестами
- Используются интерфейсы репозиториев для инверсии зависимостей
- Чистая бизнес-логика без зависимостей от инфраструктуры

## 4. Инфраструктурный слой

### Репозитории:
- `ProductDoctrineRepository` - Репозиторий товаров
- `CategoryDoctrineRepository` - Репозиторий категорий
- `CartDoctrineRepository` - Репозиторий корзин
- `OrderDoctrineRepository` - Репозиторий заказов
- `PaymentDoctrineRepository` - Репозиторий платежей

### Платежи:
- `MockPaymentGateway` - Имитация платежной системы

### Особенности:
- Все репозитории реализуют соответствующие интерфейсы из Domain слоя
- Используется Doctrine ORM для работы с БД
- Адаптеры полностью соответствуют принципам гексагональной архитектуры

## 5. API контроллеры

Реализован RESTful API с следующими endpoints:

### Товары:
- `GET /api/products` - Получить список товаров
- `GET /api/products/{id}` - Получить товар по ID
- `GET /api/products/featured` - Получить избранные товары

### Категории:
- `GET /api/categories` - Получить список категорий
- `GET /api/categories/{id}` - Получить категорию по ID

### Корзина:
- `GET /api/cart` - Получить корзину
- `POST /api/cart/items` - Добавить товар в корзину
- `DELETE /api/cart/items/{id}` - Удалить товар из корзины

### Заказы:
- `POST /api/orders` - Создать заказ
- `GET /api/orders?email={email}` - Получить заказы по email
- `GET /api/orders/{orderNumber}` - Получить заказ по номеру

### Платежи:
- `POST /api/webhooks/payment` - Вебхук платежа

### Особенности:
- Используются сессии для идентификации корзины
- Валидация входных данных
- Формат ответа: JSON с единым форматом success/error

## 6. Тестирование

### Unit тесты:
- Покрывают все Use Cases в Application слое
- Используют моки для зависимостей
- Проверяют все сценарии использования (успешные и ошибочные)

### Функциональные тесты:
- Покрывают API контроллеры
- Используют реальную БД (SQLite in-memory)
- Проверяют интеграцию всех компонентов

### Фикстуры:
- `ProductFixtures` - Фикстуры товаров
- `CategoryFixtures` - Фикстуры категорий
- `OrderFixtures` - Фикстуры заказов
- `UserFixtures` - Фикстуры пользователей

## 7. База данных

### Миграции:
- 5 миграций, реализующих схему БД
- Используется SQLite для тестирования, PostgreSQL для production
- Все таблицы соответствуют доменной модели

### Особенности:
- Сессионные корзины с автоматическим управлением
- Заказы с детализацией по товарам
- Платежи с различными статусами
- Категории с иерархической структурой

## 8. Конфигурация

### Основные особенности:
- Используется Symfony 7.2
- PHP 8.2+
- Doctrine ORM 3.3
- EasyAdmin для админ-панели
- Docker для контейнеризации

### Маршруты:
- API маршруты в `config/routes/api.yaml`
- Админ-панель на `/admin`
- Основной сайт на `/`

## 9. Админ-панель

### Особенности:
- Используется EasyAdmin Bundle
- Dashboard с метриками продаж
- CRUD для товаров, категорий и заказов
- Аутентификация пользователей
- Статистика продаж и популярных товаров

### Сервисы:
- `DashboardStatsProvider` - Сервис статистики для дашборда
